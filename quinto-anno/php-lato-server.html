Il web: client, server e siti dinamici

Il modello client-server

Ogni volta che scrivi un indirizzo nel browser si mettono a parlare due programmi, quasi sempre su due computer diversi:

  • il client, cioè il browser (Chrome, Firefox, Safari…), che chiede una risorsa e poi la mostra;
  • il server, un programma come Apache o Nginx (il web server) che resta in ascolto su una macchina in rete, riceve le richieste e risponde.

I due si capiscono grazie al protocollo HTTP (HyperText Transfer Protocol), o alla sua versione cifrata HTTPS. Lo schema non cambia mai: il client manda una richiesta, il server restituisce una risposta.

Una richiesta contiene il metodo, la risorsa desiderata e alcune intestazioni (header). Semplificata, è fatta così:

HTTP · richiesta
GET /scuola/studenti.php?classe=5A HTTP/1.1
Host: www.istituto.it
User-Agent: Mozilla/5.0 (Windows NT 10.0) Firefox/132.0
Accept-Language: it-IT

I metodi che userai quasi sempre sono due:

MetodoUso tipicoDove viaggiano i dati

POSTInviare un modulo che modifica qualcosa (registrazione, login, inserimento)Nel corpo della richiesta: non compaiono nell'URL

Il browser non sa nulla di PHPRiceve sempre e solo HTML, CSS e JavaScript. È il server che, eseguendo lo script PHP, produce l'HTML da spedire. Tienilo a mente: spiega quasi tutto quello che vedremo.

Siti statici e siti dinamici

Un sito statico è fatto di file HTML già pronti: il server li legge dal disco e li spedisce così come sono. Tutti ricevono la stessa pagina e, per cambiare un contenuto, qualcuno deve modificare il file a mano.

Un sito dinamico genera la pagina nel momento della richiesta, eseguendo un programma. Il risultato può dipendere da:

  • chi la chiede (il suo carrello, il suo nome nell'intestazione);
  • i dati inviati (le parole di una ricerca);
  • il contenuto di un database (l'elenco aggiornato dei prodotti, degli articoli, dei voti);
  • l'ora, la data, la lingua…

Registro elettronico, e-commerce, social network, forum: sono tutti siti dinamici. Scrivere a mano una pagina per ogni studente o per ogni prodotto sarebbe semplicemente impossibile.

Il viaggio di una richiesta PHP

Seguiamo che cosa succede quando il browser chiede studenti.php:

  1. il browser invia la richiesta GET /studenti.php al web server;
  2. il web server (Apache) nota l'estensione .php e passa il file all'interprete PHP;
  3. PHP esegue lo script dall'alto in basso e, se serve, si collega al DBMS (MySQL o MariaDB) e fa delle query;
  4. il database restituisce i dati, che lo script usa per costruire l'HTML;
  5. l'HTML prodotto torna al web server, che lo spedisce al browser dentro la risposta HTTP;
  6. il browser mostra la pagina. Del codice PHP non è rimasta traccia.
Una richiesta a studenti.php, passo per passo
  1. il browser invia GET /studenti.php al web server
  2. Apache vede l'estensione .php e passa il file all'interprete
  3. PHP esegue lo script e invia una query al DBMS
  4. il database restituisce le righe richieste
  5. PHP costruisce l'HTML, che torna al browser attraverso Apache
  6. il browser mostra la pagina: del PHP non c'è più traccia
pronto

Questa organizzazione si chiama architettura a tre livelli (three-tier): la presentazione nel browser, la logica applicativa sul server (Apache + PHP), i dati nel DBMS. Tra il primo e il secondo livello si parla HTTP, tra il secondo e il terzo si parla SQL.

Perché PHP

PHP (acronimo ricorsivo di PHP: Hypertext Preprocessor) nasce nel 1995 proprio per costruire pagine dinamiche ed è ancora tra i linguaggi lato server più diffusi: ci girano WordPress (che da solo muove una fetta enorme dei siti del mondo), Wikipedia, Moodle e moltissimi gestionali. Per imparare ha alcuni vantaggi concreti:

  • si mescola direttamente con l'HTML, quindi il risultato si vede subito;
  • è disponibile su quasi tutti gli hosting, anche gratuiti;
  • supporta i database in modo nativo e semplice;
  • è interpretato: niente compilazione, basta salvare il file e ricaricare la pagina.

Le basi del linguaggio

Tag PHP, istruzioni e commenti

Il codice PHP sta tra i tag <?php e ?>: tutto quello che è fuori dai tag viene spedito al browser così com'è. Ogni istruzione termina con il punto e virgola.

PHP
<?php
// Commento su una riga
#  Anche questo è un commento su una riga
/* Commento
   su più righe */

echo "Ciao mondo!";            // echo stampa nella pagina
echo "<p>Posso stampare anche HTML</p>";
print "print funziona in modo simile a echo";
✅
Due regole pratiche

In un file che contiene solo PHP si scrive il tag di apertura e si omette quello di chiusura ?>: così non rischi di spedire al browser spazi o righe vuote per sbaglio.

Per stampare un valore dentro l'HTML c'è la forma breve <?= $variabile ?>, che equivale a <?php echo $variabile; ?>.

PHP
<?php $nome = "Giulia"; ?>
<h1>Benvenuta, <?= $nome ?>!</h1>

Variabili e tipi

Le variabili cominciano con $, seguito da un nome che inizia con una lettera o un trattino basso. Maiuscole e minuscole contano: $voto e $Voto sono due variabili diverse.

Il tipo non si dichiara: PHP è a tipizzazione dinamica, cioè il tipo dipende dal valore assegnato e può cambiare durante l'esecuzione.

PHP
<?php
$nome     = "Marco";        // string (stringa)
$eta      = 18;             // int (intero)
$media    = 7.25;           // float (con la virgola: si usa il punto!)
$promosso = true;           // bool (booleano: true / false)
$materie  = ["Informatica", "Sistemi", "TPSIT"];  // array
$telefono = null;           // null: nessun valore

var_dump($media);           // float(7.25) — tipo e valore, utilissimo per il debug
echo gettype($eta);         // integer

Stringhe

Le stringhe si scrivono tra apici doppi o singoli, e la differenza conta:

  • tra doppi apici le variabili vengono sostituite dal loro valore (interpolazione) e funzionano le sequenze come \n;
  • tra apici singoli il testo è preso alla lettera.

L'operatore di concatenazione è il punto ., non il + di Java o JavaScript.

PHP
<?php
$nome = "Sara";
$classe = "5A";

echo "Ciao $nome";               // Ciao Sara
echo 'Ciao $nome';               // Ciao $nome
echo "Ciao " . $nome . "!";      // Ciao Sara!
echo "Studentessa della {$classe}";  // le graffe delimitano la variabile

$saluto = "Buongiorno";
$saluto .= " a tutti";           // .= aggiunge in coda: "Buongiorno a tutti"

Alcune funzioni sulle stringhe che userai spesso:

PHP
<?php
$s = "  Programmazione Web  ";

echo strlen($s);                      // 22 — lunghezza (spazi compresi)
echo trim($s);                        // "Programmazione Web" — toglie gli spazi ai lati
echo strtoupper($s);                  // MAIUSCOLO
echo strtolower($s);                  // minuscolo
echo ucfirst("roma");                 // Roma
echo str_replace("Web", "PHP", $s);   // sostituisce un testo con un altro
echo substr("Informatica", 0, 5);     // Infor — dalla posizione 0, 5 caratteri
echo strpos("Informatica", "ma");     // 5 — posizione della prima occorrenza
var_dump(str_contains("ciao mondo", "mondo"));  // bool(true) — da PHP 8
echo number_format(1234.5, 2, ',', '.');        // 1.234,50
⚠️

Le lettere accentatestrlen conta i byte, non i caratteri: in UTF-8 strlen("città") vale 6, perché la «à» occupa due byte. Per il testo con accenti ci sono le versioni mb_: mb_strlen("città") vale 5, e esistono anche mb_strtoupper e mb_substr.

Costanti

Una costante ha un valore che non cambia mai. Si scrive senza $ e, per convenzione, in maiuscolo.

PHP
<?php
const IVA = 0.22;
define('NOME_SCUOLA', 'ITIS Galilei');

echo NOME_SCUOLA;
echo 100 * (1 + IVA);   // 122

Operatori

Gli aritmetici, l'assegnazione combinata e l'incremento funzionano come negli altri linguaggi, con un paio di particolarità:

PHP
<?php
$a = 17; $b = 5;
echo $a + $b;        // 22
echo $a - $b;        // 12
echo $a * $b;        // 85
echo $a / $b;        // 3.4 — la divisione dà un float
echo intdiv($a, $b); // 3   — divisione intera
echo $a % $b;        // 2   — resto (modulo)
echo $a ** 2;        // 289 — potenza

$x = 10;
$x += 5;   // 15
$x *= 2;   // 30
$x++;      // 31
$x--;      // 30

PHP
<?php
$nome = $_GET['nome'] ?? 'ospite';   // se 'nome' non è nell'URL, vale 'ospite'

$voto = 5;
$esito = ($voto >= 6) ? "sufficiente" : "insufficiente";

if, elseif, else

PHP
<?php

    echo "Ottimo";

switch e match

switch confronta una variabile con una serie di valori.

PHP
<?php
$giorno = "sab";

switch ($giorno) {
    case "sab":
    case "dom":
        echo "Fine settimana";
        break;
    case "lun":
        echo "Si ricomincia";
        break;
    default:
        echo "Giorno feriale";
}
⚠️

Il break dimenticatoSe manca il break, l'esecuzione «cade» nel caso successivo e ne esegue anche le istruzioni. A volte è voluto (come per "sab" e "dom" qui sopra), molto più spesso è un errore.

Da PHP 8 c'è match, più compatto: è un'espressione (restituisce un valore), usa il confronto stretto === e non ha bisogno di break.

PHP
<?php
$codice = 404;

$messaggio = match ($codice) {
    200      => "OK",
    301, 302 => "Reindirizzamento",
    404      => "Pagina non trovata",
    default  => "Errore sconosciuto",
};

echo $messaggio;   // Pagina non trovata

Cicli

PHP
<?php
// for: quando sai quante volte ripetere
for ($i = 1; $i <= 10; $i++) {
    echo "7 x $i = " . (7 * $i) . "<br>";
}

$n = 1;
while ($n < 100) {
    $n *= 2;

Quando HTML e PHP si alternano di continuo, le parentesi graffe diventano difficili da seguire. Per questo esiste una sintassi alternativa, con i due punti e le parole endif, endforeach, endfor, endwhile: dentro le pagine è molto più leggibile.

<?php if ($loggato): ?>

<?php else: ?>
    <p><a href="login.php">Accedi</a></p>
<?php endif; ?>

<ul>
<?php for ($i = 1; $i <= 3; $i++): ?>
    <li>Elemento <?= $i ?></li>
<?php endfor; ?>
</ul>

Gli array

Un array è una variabile che contiene più valori, ognuno associato a una chiave. In PHP sono molto flessibili: le chiavi possono essere numeri oppure stringhe.

Array indicizzati

Le chiavi sono numeri che partono da 0.

PHP
<?php
$frutti = ["mela", "pera", "banana"];
echo $frutti[0];        // mela
$frutti[] = "kiwi";     // aggiunge in coda
echo count($frutti);    // 4

foreach ($frutti as $f) {
    echo "<li>$f</li>";
}

Array associativi

Le chiavi sono stringhe scelte da noi. È il modo naturale per rappresentare un «record», per esempio uno studente, ed è esattamente la forma in cui ci arriveranno le righe del database.

PHP
<?php
$studente = [
    "nome"    => "Anna",
    "cognome" => "Rossi",
    "classe"  => "5B",
    "media"   => 7.8,
];

echo $studente["cognome"];                       // Rossi
$studente["email"] = "anna.rossi@scuola.it";     // aggiunge una coppia

foreach ($studente as $chiave => $valore) {
    echo "$chiave: $valore<br>";
}

Un array può contenere altri array. Un elenco di record è un array indicizzato di array associativi: è, a tutti gli effetti, una tabella.

Funzioni e riuso del codice

Definire una funzione

PHP
<?php
function saluta(string $nome, string $saluto = "Ciao"): string
{
    return "$saluto, $nome!";
}

echo saluta("Paolo");                 // Ciao, Paolo!
echo saluta("Paolo", "Buongiorno");   // Buongiorno, Paolo!
  • I parametri possono avere un valore di default ($saluto = "Ciao").
  • Si possono indicare i tipi dei parametri e, dopo i due punti, quello del valore restituito: è facoltativo, ma consigliato.
  • return restituisce il risultato e termina la funzione.
PHP
<?php
function media(array $voti): float
{
    if (count($voti) === 0) {
        return 0;
    }
    return array_sum($voti) / count($voti);
}

function giudizio(float $m): string
{
    return match (true) {
        $m >= 9 => "ottimo",
        $m >= 7 => "buono",
        $m >= 6 => "sufficiente",

Reindirizzamenti e il pattern Post/Redirect/Get

      
La funzione header() invia intestazioni HTTP; con Location manda il browser a un'altra pagina:


PHP
<?php
header('Location: grazie.php');
exit;   // sempre exit dopo un redirect: altrimenti lo script continua!

      

        Dopo aver elaborato un form in POST conviene sempre reindirizzare. Altrimenti, se
        l'utente ricarica la pagina, il browser rispedisce il form e i dati vengono inseriti due volte.
        Lo schema si chiama Post/Redirect/Get (PRG):
      

      
    
        
  1. l'utente invia il form → richiesta POST;
    2. 
        
  2. lo script salva i dati e risponde con header('Location: ...');
    3. 
        
  3. il browser chiede la nuova pagina con GET: ricaricarla non fa danni.
    4. 
      

      

        ✕
        
«Cannot modify header information – headers already sent»header(), ma anche setcookie() e session_start(), vanno chiamate prima di qualunque output: nemmeno uno spazio o una riga vuota prima di <?php, nessun echo, nessun HTML. Le intestazioni HTTP viaggiano prima del corpo della risposta: una volta cominciato il corpo, è troppo tardi.

      


      
      
Cookie e sessioni


      
HTTP non ha memoria

      

        HTTP è un protocollo senza stato (stateless): ogni richiesta è indipendente
        dalle precedenti. Di per sé il server non sa che la richiesta delle 10:01 e quella delle 10:02 arrivano
        dalla stessa persona. Eppure un sito deve ricordarsi se hai fatto il login e che cosa c'è nel carrello.
        Le soluzioni sono due: i cookie e le sessioni.
      


      
I cookie

      
Un cookie è una piccola coppia nome = valore che il server chiede al browser di conservare. Da quel momento il browser la rimanda da solo a ogni richiesta verso lo stesso sito.


PHP
<?php
// Imposta un cookie valido 30 giorni (prima di qualunque output!)
setcookie('tema', 'scuro', [
    'expires'  => time() + 60 * 60 * 24 * 30,
    'path'     => '/',
    'httponly' => true,      // non leggibile da JavaScript
    'samesite' => 'Lax',
]);

// Lettura (disponibile dalla richiesta SUCCESSIVA)
$tema = $_COOKIE['tema'] ?? 'chiaro';

// Cancellazione: si imposta una scadenza nel passato
setcookie('tema', '', ['expires' => time() - 3600, 'path' => '/']);

      

        🍪
        
I cookie stanno nel computer dell'utenteL'utente può leggerli e modificarli quando vuole. Vanno bene per preferenze innocue (lingua, tema), mai per informazioni come «utente = admin» o «prezzo = 10».

      


      
Le sessioni

      

        Con le sessioni i dati restano sul server. Al browser viene consegnato solo un cookie con
        un codice casuale lunghissimo, l'identificativo di sessione (PHPSESSID), che il browser
        ripresenta a ogni richiesta.
      

      

        🧥
        
Come il guardaroba di un teatroIl cappotto resta al guardaroba, tu tieni in tasca soltanto il numerino. Chi ti ruba il numerino può ritirare il tuo cappotto, ma non può cambiare quello che c'è dentro: allo stesso modo, l'utente ha solo l'identificativo, mentre i dati veri (chi è, che cosa ha nel carrello) restano sul server.

      

      
In PHP usarle è semplicissimo:

      
    
        
  1. si chiama session_start() all'inizio di ogni pagina che usa la sessione, prima di qualsiasi output;
    2. 
        
  2. si leggono e si scrivono i dati nell'array $_SESSION.
    3. 
      


PHP · contatore.php
<?php
session_start();

if (!isset($_SESSION['visite'])) {
    $_SESSION['visite'] = 0;
}
$_SESSION['visite']++;

echo "Hai visitato questa pagina {$_SESSION['visite']} volte in questa sessione.";

      
Per chiudere la sessione, cioè per il logout:


PHP · logout.php
<?php
session_start();
$_SESSION = [];        // svuota i dati
session_destroy();     // distrugge la sessione sul server
header('Location: index.php');
exit;

La connessione

      
La connessione si scrive una volta sola, in un file che poi tutte le pagine includono.


PHP · db.php
<?php
$host     = 'localhost';
$dbname   = 'scuola';
$utente   = 'root';
$password = '';

$dsn = "mysql:host=$host;dbname=$dbname;charset=utf8mb4";

$opzioni = [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,  // errori come eccezioni
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,        // righe come array associativi
];

try {
    $pdo = new PDO($dsn, $utente, $password, $opzioni);
} catch (PDOException $ex) {
    // In produzione: scrivere l'errore in un log, non mostrarlo all'utente
    exit('Errore di connessione al database: ' . $ex->getMessage());
}

      
Smontiamolo pezzo per pezzo:

      
    
        
  • il DSN (Data Source Name) è una stringa che dice a PDO quale driver usare (mysql:), dove si trova il server, quale database aprire e con quale codifica (utf8mb4, che copre tutti i caratteri, emoji comprese);
    • 
        
  • new PDO(...) crea l'oggetto connessione, che salviamo in $pdo;
    • 
        
  • ERRMODE_EXCEPTION fa sì che ogni errore SQL lanci un'eccezione da intercettare con try … catch, invece di una pagina che fallisce in silenzio;
    • 
        
  • FETCH_ASSOC fa arrivare ogni riga come array associativo ['nome' => 'Anna', ...], proprio come gli array visti prima.
    •

L'attacco SQL injection

      
Vogliamo cercare gli studenti per cognome, con il valore che arriva da un form. La tentazione è incollarlo dentro la query:


PHP · codice vulnerabile
<?php
// CODICE VULNERABILE — NON FARE MAI COSÌ
$cognome = $_GET['cognome'];
$sql = "SELECT * FROM studenti WHERE cognome = '$cognome'";
$risultato = $pdo->query($sql);

      
Se l'utente scrive Rossi la query è corretta. Ma se scrive ' OR '1'='1, la query diventa:


SQL · la query che arriva al DBMS
SELECT * FROM studenti WHERE cognome = '' OR '1'='1'

      

        La condizione '1'='1' è sempre vera, quindi la query restituisce tutti gli
        studenti. Con lo stesso principio, su una pagina di login, si entra senza conoscere la password; con
        varianti più elaborate si leggono altre tabelle o si cancellano dati. È la SQL injection,
        da anni tra le vulnerabilità web più sfruttate. Il problema di fondo è che i dati dell'utente vengono
        mescolati con il codice SQL e il DBMS non riesce più a distinguerli.
      


      
La soluzione: i prepared statement

      
Con i prepared statement (istruzioni preparate) la query e i dati viaggiano separati:

      
    
        
  1. si scrive la query con dei segnaposto al posto dei valori (:cognome oppure ?);
    2. 
        
  2. si chiama prepare(): il DBMS analizza la struttura della query;
    3. 
        
  3. si chiama execute() passando i valori: il DBMS li tratta sempre e solo come dati, mai come codice SQL.
    4. 
      


PHP
<?php
require 'db.php';

$cognome = $_GET['cognome'] ?? '';

$stmt = $pdo->prepare('SELECT * FROM studenti WHERE cognome = :cognome');
$stmt->execute(['cognome' => $cognome]);
$studenti = $stmt->fetchAll();

      

        Ora, se l'utente scrive ' OR '1'='1, il database cerca uno studente il cui cognome è
        letteralmente ' OR '1'='1: non lo trova e restituisce zero righe. Attacco neutralizzato.
        Provalo qui sotto, sulla tabella studenti del database di esempio.

Gestire gli errori del database

      

        Con ERRMODE_EXCEPTION gli errori si intercettano con try … catch. Un caso tipico
        è il vincolo UNIQUE sull'email: inserire due volte la stessa email fa fallire la query con il
        codice SQLSTATE 23000.
      


PHP
<?php
require 'db.php';

try {
    $stmt = $pdo->prepare('INSERT INTO studenti (nome, cognome, classe, email)
                           VALUES (?, ?, ?, ?)');
    $stmt->execute(['Anna', 'Rossi', '5A', 'anna.rossi@scuola.it']);
    echo "Studente inserito";
} catch (PDOException $ex) {
    if ($ex->getCode() === '23000') {
        echo "Esiste già uno studente con questa email.";
    } else {
        throw $ex;   // errore imprevisto: lo lasciamo propagare
    }
}


      
Query con JOIN e funzioni di aggregazione

      
La forza del lato server è combinare i dati di più tabelle. Ecco una pagella riassuntiva con la media di ciascuno studente:


PHP · medie.php
<?php
require 'db.php';

$classe = $_GET['classe'] ?? '5A';

$sql = 'SELECT s.id, s.cognome, s.nome,
               COUNT(v.id)          AS num_voti,
               ROUND(AVG(v.voto),2) AS media
        FROM studenti s
        LEFT JOIN voti v ON v.studente_id = s.id
        WHERE s.classe = :classe
        GROUP BY s.id, s.cognome, s.nome
        ORDER BY media DESC';

$stmt = $pdo->prepare($sql);
$stmt->execute(['classe' => $classe]);
$righe = $stmt->fetchAll();
?>
<h1>Medie della classe <?= htmlspecialchars($classe) ?></h1>
<table border="1" cellpadding="6">
    <tr><th>Studente</th><th>N. voti</th><th>Media</th></tr>
    <?php foreach ($righe as $r): ?>
    <tr>
        <td><?= htmlspecialchars($r['cognome'] . ' ' . $r['nome']) ?></td>
        <td><?= $r['num_voti'] ?></td>
        <td style="color: <?= ($r['media'] !== null && $r['media'] < 6) ? 'red' : 'black' ?>">
            <?= $r['media'] ?? '—' ?>
        </td>
    </tr>
    <?php endforeach; ?>
</table>

      
Il LEFT JOIN include anche gli studenti senza voti: la loro media sarà NULL, mostrata come un trattino.


      
Le transazioni

      
Quando più query devono riuscire tutte insieme o nessuna (per esempio spostare credito da un conto all'altro), si usa una transazione:


PHP
<?php
require 'db.php';

try {
    $pdo->beginTransaction();

    $pdo->prepare('UPDATE conti SET saldo = saldo - :x WHERE id = :da')
        ->execute(['x' => 50, 'da' => 1]);
    $pdo->prepare('UPDATE conti SET saldo = saldo + :x WHERE id = :a')
        ->execute(['x' => 50, 'a' => 2]);

    $pdo->commit();      // conferma entrambe le modifiche
} catch (PDOException $ex) {
    $pdo->rollBack();    // annulla tutto
    echo "Operazione annullata";
}

Ti ricorda qualcosa?È lo stesso problema del saldo conteso visto nel ripasso sulla concorrenza: un'operazione fatta di più passi che non deve mai restare a metà. La transazione la rende atomica.

PHP · funzioni.php
<?php
session_start();

// Escape dell'output contro l'XSS
function e(?string $t): string
{
    return htmlspecialchars($t ?? '', ENT_QUOTES, 'UTF-8');
}

// Messaggi "flash": salvati in sessione e mostrati una sola volta
function flash(string $messaggio): void
{
    $_SESSION['flash'] = $messaggio;
}

function leggiFlash(): ?string
{
    $m = $_SESSION['flash'] ?? null;
    unset($_SESSION['flash']);
    return $m;
}

// Legge e valida i dati del form; restituisce [dati, errori]
function validaStudente(array $input): array
{
    $d = [
        'nome'         => trim($input['nome'] ?? ''),
        'cognome'      => trim($input['cognome'] ?? ''),
        'classe'       => strtoupper(trim($input['classe'] ?? '')),
        'email'        => trim($input['email'] ?? ''),
        'data_nascita' => trim($input['data_nascita'] ?? ''),
    ];
    $err = [];

    if ($d['nome'] === '' || mb_strlen($d['nome']) > 50) {
        $err['nome'] = 'Nome obbligatorio (max 50 caratteri).';
    }
    if ($d['cognome'] === '' || mb_strlen($d['cognome']) > 50) {
        $err['cognome'] = 'Cognome obbligatorio (max 50 caratteri).';
    }
    if (!preg_match('/^[1-5][A-Z]$/', $d['classe'])) {
        $err['classe'] = 'Classe nel formato 5A, 4B…';
    }
    if (!filter_var($d['email'], FILTER_VALIDATE_EMAIL)) {
        $err['email'] = 'Email non valida.';
    }
    if ($d['data_nascita'] === '') {
        $d['data_nascita'] = null;     // campo facoltativo
    } elseif (!DateTime::createFromFormat('Y-m-d', $d['data_nascita'])) {
        $err['data_nascita'] = 'Data non valida.';
    }

    return [$d, $err];
}

      

        💡
        
preg_match e le espressioni regolari'/^[1-5][A-Z]$/' descrive la forma ammessa: dall'inizio (^) alla fine ($) della stringa, una cifra da 1 a 5 seguita da una lettera maiuscola. preg_match restituisce 1 se il testo ha quella forma, 0 altrimenti.

modifica.php — modifica (Update)

      
La pagina riceve l'id nell'URL. Alla prima visita (GET) carica il record dal database e precompila il form; all'invio (POST) valida e aggiorna.

Area riservata: registrazione e login

      
Il login mette insieme database, form, sessioni e sicurezza. È anche il punto in cui un errore costa di più: vale la pena farlo bene.


      
Le password non si salvano mai in chiaro

      

        Se il database viene rubato (succede spesso, anche a grandi aziende) le password in chiaro sono subito
        utilizzabili, e molti usano la stessa password ovunque. Per questo nel database si salva solo un
        hash della password: il risultato di una funzione a senso unico, da cui non si
        può risalire alla password originale. PHP fa tutto con due funzioni:
      

      

        

          
FunzioneChe cosa fa

          
            
password_hash($pwd, PASSWORD_DEFAULT)Calcola l'hash (oggi con l'algoritmo bcrypt), aggiungendo da sola un valore casuale (salt)

            
password_verify($pwd, $hash)Controlla se una password corrisponde all'hash salvato

          
        

      


PHP
<?php
$hash = password_hash('Segreta123!', PASSWORD_DEFAULT);
echo $hash;   // $2y$10$Xk3...  (circa 60 caratteri, diverso a ogni esecuzione)

var_dump(password_verify('Segreta123!', $hash));   // bool(true)
var_dump(password_verify('segreta123!', $hash));   // bool(false)

      

        ✕
        
Da non usare per le passwordmd5() e sha1() non vanno bene: sono velocissime da calcolare, quindi un attaccante può provarne miliardi al secondo. E non inventarti algoritmi tuoi: password_hash è la scelta corretta.

      

      
Il salt è il motivo per cui l'hash cambia a ogni esecuzione: due utenti con la stessa password hanno hash diversi, e password_verify sa ritrovare il salt dentro l'hash stesso.

Il token anti-CSRF

      

        L'idea: ogni form contiene un valore casuale segreto, salvato anche in sessione. Un sito esterno non
        può conoscerlo, quindi le richieste falsificate che costruisce vengono rifiutate.
      


PHP
<?php
// Generazione (una volta per sessione), ad esempio in funzioni.php
if (empty($_SESSION['csrf'])) {
    $_SESSION['csrf'] = bin2hex(random_bytes(32));
}

// Verifica, all'inizio della gestione di ogni POST:
if ($_SERVER['REQUEST_METHOD'] === 'POST'
    && !hash_equals($_SESSION['csrf'], $_POST['csrf'] ?? '')) {
    http_response_code(403);
    exit('Richiesta non valida');
}

      
E in ogni form che invia in POST si aggiunge il campo nascosto:


HTML
<input type="hidden" name="csrf" value="<?= e($_SESSION['csrf']) ?>">

      

        💡
        
Perché hash_equals e non ===?hash_equals confronta due stringhe impiegando sempre lo stesso tempo, qualunque sia il punto in cui differiscono: così un attaccante non può indovinare il token un carattere alla volta misurando quanto ci mette il server a rispondere.

Da ricordare

      
    
        
  • Il browser riceve solo HTML, CSS e JavaScript: il PHP gira sul server, produce la pagina e sparisce. Le pagine si aprono da http://localhost/, mai con il doppio clic.
    • 
        
  • GET per leggere (dati nell'URL), POST per modificare (dati nel corpo). Dopo un POST riuscito, sempre redirect + exit (Post/Redirect/Get).
    • 
        
  • In PHP la concatenazione è il punto ., tra doppi apici le variabili vengono interpolate, e per confrontare si usa ===.
    • 
        
  • I dati dell'utente non sono mai affidabili: si validano sul server e, quando si stampano, si passano da htmlspecialchars (contro l'XSS).
    • 
        
  • HTTP è senza stato: i cookie stanno nel browser e l'utente può modificarli, i dati di sessione stanno sul server e il browser tiene solo il PHPSESSID. session_start(), header() e setcookie() vanno chiamate prima di qualsiasi output.
    • 
        
  • Con il database: connessione PDO in un file a parte, e ogni valore esterno passa da prepare() + execute() con i segnaposto. Mai concatenare: è la SQL injection.
    • 
        
  • CRUD = Create, Read, Update, Delete ↔ INSERT, SELECT, UPDATE, DELETE; le cancellazioni si fanno solo in POST.
    • 
        
  • Le password si salvano con password_hash e si controllano con password_verify; dopo il login session_regenerate_id(true), e ogni pagina riservata controlla da sé login e ruolo.
    •
